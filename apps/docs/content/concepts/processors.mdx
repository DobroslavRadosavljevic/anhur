Some schema helpers live in opt-in packages. Those helpers only work when the matching **processor** is registered in `defineConfig({ processors })`.

If you use the helper without the processor, the build fails with a clear error. That is intentional.

## Pairing table

| Helper                     | Package           | Processor    |
| -------------------------- | ----------------- | ------------ |
| `m.mdx()`                  | `@anhur/mdx`      | `mdx()`      |
| `md.markdown()`            | `@anhur/markdown` | `markdown()` |
| `a.image()` / `a.file()`   | `@anhur/assets`   | `assets()`   |
| `s.raw()`, `s.unique()`, … | `@anhur/core`     | none         |

## Example

```ts
import { defineCollection, defineConfig, schema as s } from "@anhur/core";
import { assets, schema as a } from "@anhur/assets";
import { mdx, schema as m } from "@anhur/mdx";

const posts = defineCollection({
  name: "posts",
  directory: "content/posts",
  include: "**/*.{md,mdx}",
  schema: s.object({
    title: s.string(),
    cover: a.image().optional(),
    body: m.mdx(),
  }),
});

export default defineConfig({
  processors: [
    mdx({ gfm: true }),
    assets({
      dir: ".anhur/assets",
      base: "/anhur-assets/",
    }),
  ],
  content: [posts],
});
```

## Body assets

When `assets()` is registered, relative images and links inside MDX/Markdown bodies are copied and rewritten to the public base. Without `assets()`, those relative body URLs fail the build.

`assets()` also accepts optional `storage` for build-time CDN upload (files-sdk). See the [Assets guide](/guides/assets#remote-storage-s3-compatible).
