**Integrations** run after codegen and per-source `onSuccess`, before the optional project `complete` hook. Use them for build-time side effects that need the final documents — search indexes, extra files, CI checks.

They are not processors. Processors pair with schema helpers (`mdx()`, `assets()`, …). Integrations go in `defineConfig({ integrations })`.

## Lifecycle

1. Validate → process → transform → `prepare`
2. Codegen → `.anhur/generated`
3. Per-source `onSuccess`
4. **`integrations`**
5. `complete`

## Package factories

Opt-in packages export a factory you put in the array:

```ts
import { orama } from "@anhur/orama";

export default defineConfig({
  content: [posts],
  integrations: [
    orama({
      collections: {
        posts: {
          schema: { title: "string" },
          index: (doc) => ({ title: doc.title }),
          store: (doc) => ({ slug: doc.slug }),
        },
      },
    }),
  ],
});
```

Plain `defineConfig({…})` is enough. `defineConfig` infers the inline `content` array and types `doc` from those collections. Do not pass `content` into the factory or write `defineConfig<typeof content>`.

## One-off hooks

```ts
import { defineIntegration } from "@anhur/core";

integrations: [
  defineIntegration({
    id: "notify",
    onComplete: async ({ outputDir, sources }) => {
      // …
    },
  }),
],
```

## Building your own package

```ts
import {
  createIntegrationConfigEntry,
  registerIntegration,
  type AnyContent,
  type IntegrationConfigEntry,
} from "@anhur/core";

export function myIntegration<TContent extends readonly AnyContent[]>(
  options: NoInfer<MyIntegrationOptions<TContent>>,
): IntegrationConfigEntry<TContent, "my-integration"> {
  return createIntegrationConfigEntry<TContent, "my-integration">(
    "my-integration",
    options,
  );
}

registerIntegration({
  id: "my-integration",
  run: async (options, context) => {
    // Run after Anhur has generated the final content.
  },
});
```

The small resolver returned by `createIntegrationConfigEntry` lets TypeScript
infer inline content before it types the package options. Apps only see the
normal `integrations: [myIntegration({…})]` API.

Runtime prefers `onComplete` on the entry; otherwise it calls the registered `run(options, context)`.
