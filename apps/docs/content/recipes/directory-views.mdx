Large static directories (proxies, providers, product catalogs) often need three shapes from the same collection:

1. A **featured / top-N** list for the homepage
2. A **key → card** map for detail routes
3. **Groups** for SEO facet / category landings

Build them once with `defineView`, `defineIndex`, and `defineGroup`.

## Config sketch

```ts title="anhur.config.ts"
import {
  defineCollection,
  defineConfig,
  defineGroup,
  defineIndex,
  defineView,
  schema as s,
} from "@anhur/core";

const providers = defineCollection({
  name: "providers",
  directory: "content/providers",
  include: "**/*.json",
  localized: false,
  generate: { split: "list-only", listOmit: [] },
  schema: s.object({
    name: s.string(),
    slug: s.slug(),
    category: s.string(),
    featured: s.boolean().optional(),
    score: s.number().optional(),
  }),
});

const featuredProviders = defineView({
  name: "featuredProviders",
  from: providers,
  where: (doc): doc is typeof doc & { featured: true } => doc.featured === true,
  generate: {
    compare: (a, b) => (b.score ?? 0) - (a.score ?? 0),
    limit: 24,
  },
});

const providerBySlug = defineIndex({
  name: "providerBySlug",
  from: providers,
  key: "slug",
  select: (doc) => ({
    name: doc.name,
    slug: doc.slug,
    category: doc.category,
  }),
});

const providersByCategory = defineGroup({
  name: "providersByCategory",
  from: providers,
  by: "category",
  select: (doc) => ({
    name: doc.name,
    slug: doc.slug,
  }),
  generate: {
    listSort: { by: "name", order: "asc" },
  },
});

export default defineConfig({
  content: [providers],
  views: [featuredProviders, providerBySlug, providersByCategory],
});
```

## App usage

```ts
import { allFeaturedProviders, providerBySlug, providersByCategory } from "anhur/generated";

allFeaturedProviders; // T[]
providerBySlug["acme"]?.name; // Record with literal keys in .d.ts
providersByCategory.find((g) => g.key === "vpn")?.items;
```

## Why not filter at runtime?

- Huge `allProviders` arrays still ship every field you left on the list
- Detail routes want O(1) lookup without a getter (`list-only` has none)
- Category pages want pre-bucketed `{ key, count, items }` for SSG

Indexes and groups also emit **literal key unions** (`ProviderBySlugKey`, …) so typos fail typecheck.

See [defineView](/reference/define-view) and the [YAML / JSON catalog](/recipes/yaml-json-catalog) recipe.
