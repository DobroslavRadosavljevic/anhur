Every collection and singleton needs a `schema`. Anhur uses Zod (via `schema as s` from `@anhur/core`) plus a few content-oriented helpers.

## Core helpers

```ts
import { schema as s } from "@anhur/core";

s.object({
  title: s.string(),
  slug: s.unique(),
  publishedAt: s.isodate().optional(),
  body: s.raw(),
  excerpt: s.excerpt({ length: 160 }).optional(),
  toc: s.toc({ maxDepth: 3 }).optional(),
  author: s.reference("authors", { embed: true }),
});
```

| Helper                            | Purpose                                              |
| --------------------------------- | ---------------------------------------------------- |
| `s.raw()`                         | Uncompiled body / string blob                        |
| `s.slug()`                        | Slug-shaped string                                   |
| `s.unique()`                      | Unique in the collection (per locale when localized) |
| `s.reference("name", { embed? })` | Cross-collection reference                           |
| `s.isodate()`                     | ISO date string                                      |
| `s.excerpt({ length? })`          | Excerpt from body                                    |
| `s.metadata()`                    | Document metadata object                             |
| `s.toc({ maxDepth? })`            | Table of contents                                    |

Normal Zod APIs work: `.optional()`, `.transform()`, unions, and so on.

Inside schema `.transform`, `getDocumentMeta()` from `@anhur/core` gives id, locale, and path info.

## Opt-in helpers

| Import                                | Field                   |
| ------------------------------------- | ----------------------- |
| `schema as m` from `@anhur/mdx`       | `m.mdx()`               |
| `schema as md` from `@anhur/markdown` | `md.markdown()`         |
| `schema as a` from `@anhur/assets`    | `a.image()`, `a.file()` |

These require matching [processors](/concepts/processors).
