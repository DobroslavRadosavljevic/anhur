Derived exports live under `defineConfig({ views })`. Three shapes:

| Helper        | Emits                     | Best for                        |
| ------------- | ------------------------- | ------------------------------- |
| `defineView`  | `T[]`                     | featured / top-N / merged feeds |
| `defineIndex` | `Record<string, T>`       | detail lookup by slug/sku       |
| `defineGroup` | `{ key, count, items }[]` | facet / SEO landing pages       |

All run after transforms and `prepare`. They are list-only (no getters / `documents/` modules).

```ts
import {
  defineCollection,
  defineConfig,
  defineGroup,
  defineIndex,
  defineView,
  schema as s,
} from "@anhur/core";

const products = defineCollection({
  name: "products",
  directory: "content/products",
  include: "**/*.json",
  localized: false,
  schema: s.object({
    name: s.string(),
    sku: s.string(),
    category: s.string(),
    featured: s.boolean().optional(),
    price: s.string(),
  }),
});

const featuredProducts = defineView({
  name: "featuredProducts",
  from: products,
  where: (doc): doc is typeof doc & { featured: true } => doc.featured === true,
  generate: {
    listSort: { by: "price", order: "asc" },
    limit: 12,
  },
});

const productBySku = defineIndex({
  name: "productBySku",
  from: products,
  key: "sku",
  select: (doc) => ({
    name: doc.name,
    sku: doc.sku,
    price: doc.price,
  }),
});

const productsByCategory = defineGroup({
  name: "productsByCategory",
  from: products,
  by: "category",
  select: (doc) => ({
    name: doc.name,
    sku: doc.sku,
    price: doc.price,
  }),
});

export default defineConfig({
  content: [products],
  views: [featuredProducts, productBySku, productsByCategory],
});
```

```ts
import { allFeaturedProducts, productBySku, productsByCategory } from "anhur/generated";

productBySku["PRO"]?.price;
productsByCategory.find((g) => g.key === "pro")?.items;
```

## Shared options

`where` / `select` receive `(document, ctx)`. Use `ctx.documents("authors")` (or the collection object) for joins — same idea as collection `transform`.

`generate`:

| Field      | Notes                                                      |
| ---------- | ---------------------------------------------------------- |
| `listOmit` | Override inherited light-list omit before `select`         |
| `listSort` | `{ by, order? }`                                           |
| `compare`  | Custom comparator (wins over `listSort`)                   |
| `limit`    | Cap rows after sort (views: whole list; groups: per group) |

## defineView

- **One collection** — `where` and optional `select`
- **Two or more** — `select` required; rows are tagged with `collection`
- Default export: `allFeaturedProducts` from `name` (set `listName` when the name is irregular)

## defineIndex

- Single collection + `key` (field name or function)
- Duplicate keys fail the build
- Default export: the `name` itself (`productBySku`)

## defineGroup

- Single collection + `by` (field name or function)
- Emits `{ key, count, items }[]` sorted by `key`
- Default export: the `name` itself (`productsByCategory`)

## Types

Generated `.d.ts` uses `GetViewByName<typeof configuration, "featuredProducts">` for the **item** type of views, indexes, and groups. `GetViewByName` remaps `s.reference(..., { embed: true })` the same way as `GetTypeByName`, so view items stay assignable to collection light-list types when shapes match.

Light list aliases use `OmitListFields<…>` (not plain `Omit`) so omitted keys such as `body` are also stripped from nested embeds — matching runtime list exports.

Indexes and groups also emit **literal key unions** from the build:

```ts
export type ProductBySkuKey = "PRO" | "PRO2";
export type ProductBySkuMap = Record<ProductBySkuKey, ProductBySku>;

export type ProductsByCategoryKey = "pro" | "starter";
export type ProductsByCategoryGroup = {
  key: ProductsByCategoryKey;
  count: number;
  items: Array<ProductsByCategory>;
};
```

In config, `key` / `by` string fields are typed as the collection’s string fields (not `featured: boolean`). Type-predicate `where` + `select` narrows the document into `select`. `ctx.documents(products)` is typed when you pass the collection object.

### Embed fields in callbacks

Generated exports remap embeds automatically. For `where` / `select` / `by` / `key` callbacks that read embedded fields (e.g. `doc.provider.slug`), pass the same content array as `defineConfig`:

```ts
const content = [providers, proxies] as const;

defineGroup({
  name: "proxiesByProvider",
  content,
  from: proxies,
  by: (doc) => doc.provider.slug,
});
```

Or bind once with `createDerivedHelpers(content)` so each call inherits remapping.

See also [defineConfig](/reference/define-config) (`views`).
